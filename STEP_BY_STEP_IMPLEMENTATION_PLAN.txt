3. SECTION 1: DOMAIN DATA MODEL, AUDIT & PERSISTENCE ENGINE (Milestone 1)
================================================================================
Goal: Implement the relational entities, composite indices, and locking repository queries.

[x] Step 1.1: Create Enumerations

[x] Step 1.2: Build JPA Entities
    - Book: id, isbn (13 digits unique), title, author, edition
    - Branch: id, code (unique, e.g., 'CS-DEPT', 'CENTRAL'), name, contact_email

    - User: id, university_id, full_name, email, password_hash, role
    - TransferRequest: id, copy (FK), student (FK), from_branch (FK), to_branch (FK), status, created_at, expires_at
    - Loan: id, copy (FK), student (FK), issue_date, due_date, return_date, fine_amount
    - AuditLog: id, entity_name, entity_id, from_status, to_status, operator_id, recorded_at

[x] Step 1.3: Define Database Indexes (NFR-2 Performance benchmark < 350ms)
    - Composite Index on books (title, author)
    - Composite Index on branch_copies (branch_id, status)
    - Unique index on branch_copies (barcode)
    - Index on transfer_requests (copy_id, status)

[x] Step 1.4: Repository Layer & Pessimistic Lock Query
    - BranchCopyRepository:

6. SECTION 4: TRANSFER STATE MACHINE & CONCURRENCY CONTROLS (Milestone 3)
================================================================================
Goal: Implement the core intra-campus transfer workflow with pessimistic row locking.

[x] Step 4.1: Transfer Request Service with Pessimistic Locking (NFR-1)
    - Method: requestTransfer(Long copyId, Long destinationBranchId, Long studentId)
    - Transaction: @Transactional(isolation = Isolation.READ_COMMITTED)
    - Acquires write lock on BranchCopy via findByIdForUpdate(copyId) (SELECT ... FOR UPDATE).
    - Validation: Throws ConflictException (HTTP 409) if not AVAILABLE.
    - Transitions copy to RESERVED and creates TransferRequest (REQUESTED).
    - Appends immutable entries to AuditLog table.

[x] Step 4.2: Dispatch Endpoint (ROLE_LIBRARIAN)
    - PUT /api/v1/transfers/{id}/dispatch
    - Source librarian marks item shipped to transit team.
    - Transitions copy to IN_TRANSIT and transfer to DISPATCHED.
    - Appends immutable audit entry.

[x] Step 4.3: Receive Endpoint (ROLE_LIBRARIAN)
    - PUT /api/v1/transfers/{id}/receive
    - Destination branch acknowledges arrival.
    - Transitions copy to READY_PICKUP and re-assigns physical current_branch.
    - Sets expires_at = now + 48 hours for student pickup window.
    - Appends immutable audit entry.

[x] Operational Endpoints & Concurrency Verification
    - GET /api/v1/transfers/my-requests (Student tracking)
    - GET /api/v1/transfers/queue (Librarian workflow dashboard)
    - Verified via TransferStateFlowTest (Full linear state machine test)
    - Verified via TransferConcurrencyTest (10 concurrent threads: 1 Success, 9 HTTP 409 Conflicts)

7. SECTION 5: CIRCULATION, AUDIT LOGGING & SCHEDULED DAEMONS (Milestone 3)
================================================================================
Goal: Implement checkout, returns, audit persistence, and automated background jobs.

[x] Step 5.1: Physical Barcode Checkout (ROLE_LIBRARIAN)
    - POST /api/v1/loans/checkout
    - Body: { "barcode": "BC-10924", "studentId": 42 }
    - Validates copy status (READY_PICKUP for the student or AVAILABLE).
    - Transitions copy to ISSUED, creates 14-day Loan record, completes any associated transfer.
    - Appends immutable audit entry to audit_logs.

[x] Step 5.2: Book Return Endpoint (ROLE_LIBRARIAN)
    - POST /api/v1/loans/{id}/return
    - Marks return_date = today, restores copy to AVAILABLE at return branch.
    - Calculates final fine if overdue.
    - Appends immutable audit entry.

[x] Step 5.3: Automated Hold Expiry Daemon (Section 4.1)
    - HoldExpiryScheduler: runs every minute to inspect 48-hour pickup window.
    - Finds all TransferRequests with status == READY_FOR_PICKUP and expires_at < now.
    - Reverts copy.status = AVAILABLE, marks transfer.status = EXPIRED, logs audit trail.

[x] Step 5.4: Midnight Overdue Fine Calculation Daemon (Section 4.1)
    - OverdueFineScheduler: scheduled at midnight (cron = "0 0 0 * * ?").
    - Formula: Fine Amount = Days Elapsed Past Due * ₹5.00 per non-returned book.
    - Automatically updates active overdue loans in database.

[x] Step 5.5: Audit Trail Service & Query APIs (NFR-4)
    - AdminAuditController: GET /api/v1/admin/audit-logs, GET /api/v1/admin/audit-logs/entity/{entityName}/{entityId}.
    - GET /api/v1/loans/my-loans (Student loan and fine inspection).
    - GET /api/v1/loans/active (Librarian overview of active circulation).
    - Verified via CirculationAndSchedulerTest (3 passing integration tests)
